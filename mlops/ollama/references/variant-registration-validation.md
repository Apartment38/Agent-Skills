# Register and verify local variants without new weights

1. Discover the service endpoint and query /api/tags before deciding whether installation is needed. A refused connection is not an empty inventory. If startup failed on a model directory under a mounted filesystem, compare service and mount timestamps before changing permissions. Starting the existing unit may require interactive authentication; do not bypass it by launching an unapproved parallel daemon.
2. Preserve original tags and inventory. Read /api/show for every distinct model: parameter count, native context, capabilities, template, parameters and projector metadata. /api/tags can omit multimodal capabilities present in /api/show. Deduplicate by manifest digest and weight/projector layer identities. Use total, not effective/active, parameter counts.
3. Fetch publisher cards and generation_config.json for each model. Matching family sampling settings are legitimate when independently documented. Distinguish publisher settings from hardware thread/batch choices and disclose unencoded generation-config controls.
4. Inherit FROM an installed tag; avoid reconstructing from one GGUF blob, which may lose projectors, parsers, templates and stopping behavior. No unnecessary SYSTEM/TEMPLATE changes. Use exact context sizes in names; 1K=1024.
5. Installation scripts must preflight base presence and exact digest, refuse unapproved changes, and never pull automatically. Save Modelfiles, manifest, sources and results. Verify registered /api/show and unchanged original digests after creation.
6. Compare base/derived non-parameter layers by mediaType, digest and size. The layer `from` provenance annotation changes legitimately and is not a weight difference. Compare renderer/parser configuration blobs too: an empty template can mean a built-in renderer, not missing tool formatting.
7. Test sequentially with bounded tokens and timeouts that allow cold loading. Inspect structured tool_calls and argument values on both native and OpenAI-compatible APIs; never execute generated calls. For embeddings check count, dimension, finiteness and nonzero vectors; use truncate=false. Retain failures and investigated causes.
8. Inspect runner n_ctx/n_ctx_slot as well as /api/ps: saved/requested context alone does not prove effective allocation. Save offloaded layer counts and CPU/GPU model/KV buffers. CPU-mapped tensors can remain even when every transformer layer is offloaded; API size_vram is not complete physical accounting.
9. Sequential requests may leave multiple models resident. Record co-residency and repeat an embedding or latency test in isolation if it affected placement. Do not evict unrelated active clients without need or permission. Preserve automatic GPU placement unless measurements justify an override.
10. Document client overrides, reasoning as a request-level control, output/tool-schema headroom, concurrency and the exact remote endpoint. Test LAN address locally but distinguish that from remote-client reachability. Warn that an Ollama dummy API key is not authentication.
